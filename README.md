# Canon LBP-810: нативная печать в Windows 10 x64

Экспериментальный драйвер с локальным обработчиком CAPT. Виртуальная машина не нужна.
Системный Unidrv превращает текст и графику приложения в монохромный растр,
а наш процесс x64 сжимает его и передаёт LBP-810 через штатный `usbprint.sys`.

## Проверено на подключённом принтере

- Windows 10 x64, сборка 19045; USB `04A9:260A`.
- Нативные запросы CAPT и ответы статуса.
- Прямая печать рамки, сетки и полос через USB: результат подтверждён пользователем.
- Печать через очередь Windows: русский текст, латиница и прямоугольник;
  результат подтверждён пользователем.
- Сжатие/независимое декодирование белой, чёрной, тестовой и случайной страниц.
- Две страницы одним заданием через Windows: после повторной проверки
  оба листа с номерами 1 и 2 напечатаны правильно, результат подтверждён пользователем.
  На первой попытке были статусы неготовой бумаги и занятого буфера;
  перед успешным повтором выполнен стандартный USB soft reset.
- Альбомная A4: Windows сообщает область 6736 × 4736 точек, Unidrv
  выполняет программный поворот через `LANDSCAPE_CC270`. На физическом листе
  проверены русский текст и метки правого/нижнего края: обрезки нет,
  результат подтверждён пользователем.

## Использование

### Установщик для другого компьютера

Скопируйте `dist/LBP810-Native-Setup-0.2.0-x64.exe` на компьютер с Windows 10
22H2 x64 (сборка 19045) или новее. Запустите файл, подтвердите запрос
администратора и установку, затем подключите и включите принтер по USB.
В диалоге печати выберите **Canon LBP-810 Native**.

В установщик включён .NET 10: отдельно устанавливать .NET, SDK, Visual Studio
или драйвер Canon для XP не нужно. Интернет для установки не требуется.
Это независимый драйвер сообщества, а не официальный продукт Canon;
исполняемый файл пока без цифровой подписи.

Файлы устанавливаются в `C:\Program Files\Canon LBP-810 Native`.
Служба `Lbp810NativeBridge` автоматически запускается при загрузке Windows
и работает независимо от входа пользователя. LBP-810 определяется по USB
`04A9:260A` при каждом задании: привязки к серийному номеру или USB-порту нет.
При подключении нескольких LBP-810 автоматический выбор намеренно отклоняется.
Принтер может быть выключен во время установки; перед печатью его нужно включить.

Удаление: «Параметры → Приложения → Canon LBP-810 Native (Community Driver)»
или `Uninstall.exe` в папке установки. Очередь, служба и файлы удаляются,
диагностические журналы в `C:\ProgramData\Lbp810Native` сохраняются.
Если Windows ещё держит драйвер открытым, его неактивная запись Unidrv/GPD
может остаться в системном кэше; это записывается в `uninstall.log`.
Очередь, служба и файлы приложения при этом удаляются. Общий диспетчер
печати других принтеров установщик не перезапускает.
При незавершённых заданиях установка/удаление останавливается: сначала
дождитесь печати или отмените задания в очереди.

Установщик использует системные компоненты Unidrv установленной Windows,
не распространяет DLL Windows из этого компьютера и не заменяет общие DLL.
Если компоненты печати отсутствуют в урезанной сборке Windows, он сообщает ошибку.
Повторный запуск установщика обновляет существующую установку.

Для переноса достаточно одного Setup EXE. Рядом в `dist` находятся архив
исходников GPL `LBP810-Native-Source-0.2.0.zip` и контрольная сумма
`SHA256SUMS.txt`. После установки рабочая копия не зависит от `D:\projects\LBP810`.

### Режим разработки из папки проекта

В диалоге печати приложения выберите **Canon LBP-810 Native**.
Текущая версия поддерживает A4, книжную и альбомную ориентацию,
монохромную печать 600 dpi. Выберите ориентацию в настройках печати приложения
или свойствах принтера; книжная остаётся вариантом по умолчанию.
Точная калибровка полей и другие форматы бумаги пока не проверены.

В режиме разработки обработчик запускается при входе пользователя через ярлык
`Canon LBP-810 Native.lnk` в папке автозагрузки. Он слушает только
`127.0.0.1:18100`; принтер остаётся подключён по USB.
Ручной запуск: `scripts/Start-BridgeBackground.ps1`.
Для запуска в видимой консоли используйте `scripts/Start-Bridge.ps1`.
Не запускайте два обработчика одновременно.

Фоновый запуск использует `auto`: ищется единственный подключённый LBP-810.
Если установлена служба, проектный скрипт не запускает второй обработчик.

Проектный запуск требует установленного .NET 10 и файлов проекта.
Установщик выше использует автономную сборку и снимает эти зависимости.

## Сборка и диагностика

```powershell
dotnet build src/Lbp810 -c Release
dotnet run --project src/Lbp810 -c Release --no-build -- selftest
dotnet run --project src/Lbp810 -c Release --no-build -- list
dotnet run --project src/Lbp810 -c Release --no-build -- windows-test-landscape
dotnet run --project src/Lbp810 -c Release --no-build -- help
```

Сборка установщика: `scripts/Build-Installer.ps1`. Для неё нужны SDK .NET 10,
Visual C++ x64 и Windows SDK (компилятор ресурсов). Первый запуск может
скачать runtime-пакеты из NuGet; установщик для конечного пользователя
после этого автономен. Исходники установщика находятся в `installer`.
Пакет содержит COPYING и лицензии/уведомления сторонних компонентов .NET.

Команда `LBP810-Native-Setup-0.2.0-x64.exe /verify` проверяет распаковку,
SHA-256 всех файлов и запуск тестов на включённом runtime, не устанавливая
службу или очередь. `/quiet` отключает диалоги установщика, но не запрос UAC.

Повторная установка очереди: `scripts/Install-Queue.ps1` от администратора.
Скрипт регистрирует наш GPD, использует уже установленные системные DLL
Unidrv и создаёт только нашу очередь и локальный TCP-порт.

В режиме разработки технические журналы находятся в `artifacts/jobs`, журнал фонового запуска —
в `artifacts/bridge.stdout.log` и `artifacts/bridge.stderr.log`.
Рабочий режим не сохраняет изображения новых документов. Режим `capture`
намеренно сохраняет PBM-страницы для диагностики и не обращается к USB.
PBM и журналы тестовых запусков остаются в `artifacts`.

При таймауте автоматической повторной передачи страницы нет: иначе возможны
неожиданные дубликаты. Отображение ошибок CAPT в статусе очереди Windows
ещё не реализовано; статус «отправлено» не доказывает физическую печать.
Пока нет надёжной обработки отключения USB, замятия и восстановления задания.
При зависшем состоянии можно остановить обработчик, выполнить `reset DEVICE`
(используя точный путь из `list`) и снова запустить обработчик.
Сброс выполняйте только при отсутствии нужного незавершённого задания.

Для удаления только проектной установки используйте `scripts/Uninstall-Queue.ps1` от администратора.
Он останавливает наш обработчик, удаляет нашу очередь, порт, регистрацию
драйвера и ярлык автозагрузки. Исходники, бинарные файлы и журналы сохраняются.

## Исходники и лицензия

Новая реализация CAPT: `src/Lbp810`. Описание системного минидрайвера:
`driver/LBP810.GPD`. Старый пакет Canon в `l340benx` не изменялся и не используется.

Команды и формат CAPT основаны на открытом драйвере Nicolas Boichat (2004),
в котором часть подходов заимствована у Rildo Pragana (2000).
Эталонная копия: `third_party/capt-reference`, commit
`c66806ae72afc241201d33990a8827daa7398e10`.
Чужие Linux-бинарные файлы из эталонного репозитория не запускаются.
Новые исходники распространяются по GPL-2.0-or-later; полный текст — `COPYING`.
Исходный пакет Canon сохраняет собственную лицензию.

## Проверка установщика

На рабочем компьютере с Windows 10 x64 проверены `/verify`, установка
из одного EXE, автообнаружение USB, запуск службы, обновление, удаление
и повторная установка. После удаления проверено отсутствие папки программы,
очереди, порта и службы; после повторной установки очередь имеет статус Normal,
служба — Running/Automatic. Печать альбомного листа из автономной установленной
копии подтверждена пользователем. Чистый второй компьютер и Windows 11 требуют отдельного
испытания: наличие установленной здесь печатной подсистемы не заменяет такую проверку.
